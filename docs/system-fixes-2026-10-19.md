**บันทึกการแก้ไข MealQ — 19 ตุลาคม 2026**

แก้ข้อบกพร่องทั้ง 13 รายการจากรายงานรีวิว และเพิ่มส่วนที่ยังไม่เชื่อมกันระหว่างหน้าจอกับ Backend

| ปัญหาจากรีวิว | ผลหลังแก้ |
|---|---|
| Checkout ซ้ำ | Frontend เก็บ key ของคำขอใน sessionStorage/route และ Backend มี unique index ต่อบัญชี/คำขอ ส่งซ้ำได้ออเดอร์เดิม ไม่หัก Wallet ซ้ำ ตรวจ body ที่เปลี่ยนและยอดก่อนจ่ายด้วย |
| เจ้าของร้านถูกระงับ | ปิดรับออเดอร์ของร้าน และ checkout ตรวจเจ้าของร้านอีกชั้น บัญชีเก่าถูกเพิกถอนตามเดิม |
| QR รหัสซ้ำ | QR ใหม่บรรจุเลขออเดอร์และรหัส 4 หลัก ตัวอ่านปฏิเสธ QR ตัวเลขแบบเก่าถ้าตรงหลายออเดอร์ |
| Production checkout | แสดงช่องทางที่ Backend รองรับจริง มี Wallet ใน Checkout และหน้า Wallet สำหรับยอด/ประวัติ/เติมยอดทดสอบ |
| ตัวเลือกเมนูไม่บันทึก | Controller ใช้ validation ที่มีอยู่ บันทึกและแก้ optionGroups ได้ |
| รูปร้านไม่บันทึก | รองรับ logo/coverImage รวมการล้างรูปและตรวจชนิด/ขนาดข้อมูล |
| คิวและเวลาคงที่ | Backend ส่งคิวที่กำลังทำ เลขคิวถัดไป คิวที่ยังรอ และเวลาประมาณตามภาระงาน/เวลาทำของเมนู ไม่แสดงคิว #0 เมื่อยังไม่มีรายการกำลังทำ |
| ส่วนลดไม่ตรง | สองฝั่งปัดทศนิยมสองตำแหน่งตรงกัน และ Backend ปฏิเสธยอดที่เปลี่ยนจากที่ลูกค้ายืนยัน |
| ข้อความคืนเงิน | Merchant เห็นว่า Wallet คืนอัตโนมัติ ส่วน sandbox ไม่มีเงินจริงต้องคืน |
| ตัวเลือกอาหารไม่ครบกติกา | ตรวจ min/max/ตัวเลือกที่ปิดขายก่อนเพิ่มลงตะกร้าและก่อน checkout |
| ประวัติชื่อตัวเลือกเปลี่ยน | เก็บชื่อและราคาตัวเลือกใน Order ตอนสั่ง Customer/Merchant ใช้ snapshot สำหรับออเดอร์ใหม่ |
| Validation มี test แต่ไม่ต่อ API | เชื่อมกับ route จริง และเพิ่มการทดสอบ HTTP ที่ตรวจการบันทึกกับ boolean ที่ผิดชนิด |
| เรียงใกล้สุดไม่ทำงาน | Merchant ใส่พิกัดร้านได้ Customer ขอใช้ตำแหน่งเมื่อเลือกเรียงใกล้สุด คำนวณระยะทางจากพิกัด ร้านที่ไม่มีพิกัดอยู่ท้ายรายการ |

ส่วนที่เพิ่มจากรายการฟีเจอร์ค้าง:

- Admin Settings บันทึกค่าบริการและสถานะรับออเดอร์รวมใน MongoDB ค่าปัจจุบันเผยแพร่ผ่าน `/api/v1/config`
- Admin ส่งคำขอตั้งรหัสผ่านผ่าน API ได้ ใช้ token หมดอายุ/ใช้ครั้งเดียวแบบเดียวกับหน้าลืมรหัสผ่าน มี audit log ใน development แสดงลิงก์ทดสอบ ส่วน production ใช้ SMTP
- Admin กำหนดบัญชี `staff` ให้ร้านได้ พนักงานใช้ Merchant portal และเข้าข้อมูลของร้านที่ได้รับมอบหมาย รวม Socket.IO room
- สวิตช์โปรโมชันสร้างการแจ้งเตือนในแอปจากคูปองที่เปิดใช้งาน ไม่สร้างรายการเดิมซ้ำ และไม่ถูกล้างทิ้งเมื่อโหลดออเดอร์
- `.env.example` ใช้ MongoDB port 27018 ตรงกับ Compose โดยไม่แก้ `docker-compose.yml` ที่มีการแก้ไขอยู่ก่อนหน้า
- ปรับคู่มือหลักและทำเครื่องหมายเอกสารออกแบบเก่า เพื่อแยกสถานะปัจจุบันกับ mock เดิม

**ผลทดสอบ**

- Backend unit/HTTP tests: ผ่าน 38 รายการ โดย MongoDB test ถูกข้ามในโหมดปกติ
- รัน MongoDB concurrency test แยก: ผ่าน 1 รายการ
- Workflow integration เดิม: ผ่าน 10 กลุ่ม บนฐานข้อมูลแยก
- Regression integration ใหม่: ผ่าน 6 กลุ่ม ใช้ฐานข้อมูลชั่วคราวและเปิด Backend ทั้ง development/production เพื่อยืนยันการหัก Wallet ครั้งเดียว, เมนู/รูป, คิว, staff, suspension, settings และ production Wallet
- Frontend tests: ผ่าน 7 รายการ ครอบคลุมการปัดราคา, กติกาตัวเลือก, QR ซ้ำ, ประวัติ, โปรโมชัน, key ข้าม retry/reload และระยะทาง
- Frontend lint/build: ผ่าน

คำสั่งตรวจ:

```powershell
cd backend
npm.cmd test
npm.cmd run test:regression
npm.cmd run test:integration # ต้องมี Backend และบัญชี seed

cd ..\frontend
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

**ข้อจำกัดที่ยังต้องตั้งค่าหรือทดสอบเพิ่มเติม**

- เงินผ่านบัตร/PromptPay/ธนาคารจริงและเติมเงินจริงยังต้องเชื่อม payment provider และ callback ที่ตรวจสอบได้ Production เปิดเฉพาะ Wallet และไม่จำลองว่าจ่ายเงินจริงสำเร็จ
- Google OAuth และ SMTP มีโค้ดรองรับ แต่ยังไม่มี credentials จึงยังไม่ได้ทดสอบกับผู้ให้บริการจริง
- การแจ้งเตือนเป็นในแอป ไม่มี Web Push ขณะปิดเว็บ
- พิกัดร้านต้องกรอกก่อนใช้การเรียงใกล้สุด ตำแหน่งลูกค้าใช้ในเบราว์เซอร์เพื่อคำนวณระยะทาง ไม่ส่งไป Backend และต้องให้ผู้ใช้อนุญาต
- Snapshot ของชื่อ/ราคาตัวเลือกใช้กับออเดอร์ใหม่ ข้อมูลเก่าที่ไม่ได้เก็บ snapshot ไม่สามารถสร้างประวัติเดิมที่สูญหายคืนได้
- หาก Backend หยุดกลาง checkout ก่อนบันทึกผลสำเร็จ คำขอนั้นจะถูกกันไว้เป็น in-progress เพื่อไม่หักเงินซ้ำ ยังไม่มี worker กระทบยอดอัตโนมัติ ต้องตรวจออเดอร์/Wallet ก่อนสร้างคำขอใหม่
- ยังไม่ได้ทดสอบหน้าจอด้วยเบราว์เซอร์จริง กล้องจริง การอนุญาตตำแหน่ง และการ reconnect Socket.IO เพราะเครื่องมือในเซสชันไม่มีเบราว์เซอร์ให้เชื่อมต่อ
- รูปยังเก็บเป็น data URL ใน MongoDB และ build มีคำเตือน bundle ใหญ่ ควรแยกจัดการ storage และประสิทธิภาพเมื่อเตรียมเปิดสาธารณะ
