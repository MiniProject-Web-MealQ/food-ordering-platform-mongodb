# หน้า Home ใช้ข้อมูลร้านและรูปจริง

หน้า `/` โหลดร้านและเมนูจาก public API `/restaurants` และ `/menus` ชุดเดียวกับหน้าลูกค้า โดยไม่ต้องเข้าสู่ระบบ ข้อมูลจากทั้งสอง endpoint จะอัปเดตพร้อมกัน เพื่อไม่ผสมร้านเก่ากับเมนูใหม่ระหว่างรีเฟรช

- ภาพหลักใช้รูปอาหารที่พร้อมขาย พร้อมโลโก้ ชื่อร้าน สถานะ และจำนวนร้าน/เมนูจริง หากไม่มีรูปอาหารจะใช้แบนเนอร์ร้าน
- การ์ดร้านใช้แบนเนอร์ โลโก้ หมวดอาหาร จำนวนเมนู สถานะเปิดร้าน และข้อมูลรีวิวจริง ไม่สร้างคะแนนหรือคิวตัวอย่าง
- โหลดใหม่เมื่อกลับเข้าแท็บและทุก 30 วินาทีขณะหน้าแสดงอยู่ จำกัดเวลาโหลด 15 วินาที มี retry และเก็บข้อมูลล่าสุดไว้หากรีเฟรชไม่สำเร็จ
- ปุ่มหลักไปหน้าเลือกร้าน และการ์ดไปหน้ารายละเอียดร้านโดยใช้รหัสที่ API ส่งมา กรองร้านที่ระงับและเมนูที่ไม่มีร้านแล้ว

การตรวจบน Windows: frontend 68 tests ผ่าน รวม 4 tests สำหรับการแปลงข้อมูล public catalogue/การโหลดสอง endpoint พร้อมกัน, ESLint และ production build ผ่าน ไม่ได้ทดสอบภาพหรือคลิกผ่าน browser เนื่องจากสิทธิ์ origin ที่บันทึกไว้ปฏิเสธการควบคุม

การนำขึ้น Pi ใช้ `deploy/release-home-sync-pi.sh` สร้าง release ใหม่ สำรองเต็มและตรวจ hash ก่อนสลับเฉพาะ web พร้อมตรวจ ID/start time ของ API, MongoDB, Tunnel และเว็บโปรเจคอื่น เก็บ release/image และจุด rollback เดิมไว้ทั้งหมด ไม่ล้างข้อมูลร้านหรือเมนูซ้ำ

ขึ้น production release `20261019-home-catalogue-sync` แล้ว ตรวจ HTTPS root/entry asset ตรงชุด build, API/DB healthy, รูป WebP 60 ภาพตรง SHA256 ต้นฉบับ, www redirect และเว็บโปรเจคเดิมผ่าน ขณะตรวจ live catalogue เป็น 7 ร้าน/49 เมนู ซึ่งรวมข้อมูลที่เพิ่มเข้ามาหลังชุด seed แล้ว
