# MealQ: สำรองอัตโนมัติและทดลองกู้คืน

ตั้งค่าบน Pi และเครื่อง Windows วันที่ 19 ตุลาคม 2026 เวลาไทย โดยไม่ restart แอป ไม่แก้ฐานข้อมูลจริง และไม่ลบไฟล์ข้อมูล/backup, container หรือ volume

## งานที่ติดตั้ง

| เครื่อง | งาน | เวลา Asia/Bangkok | ตำแหน่ง |
| --- | --- | --- | --- |
| Pi | crontab ของ linapspi4 | ทุกวัน 03:35 | `/home/linapspi4/mealq-app/shared/operations/backup-pi.sh` |
| Windows | Task Scheduler: `MealQ-OffPi-Backup` | ทุกวัน 04:10 | `C:\Users\game_\MealQBackups\operations\backup-sync-windows.ps1` |

คง cron ต่ออายุ certificate เดิมเวลา 03:15 ไว้ครบ สำรอง crontab ก่อนเปลี่ยนทุกครั้งใน `shared/backups/operations-before-<timestamp>/` และเก็บ task XML/สคริปต์เดิมบน Windows ใน `MealQBackups\installation-history\<timestamp>\` ก่อนอัปเดต

Pi ใช้ timezone +07; Windows ใช้ `SE Asia Standard Time` เวลาไทยทั้งคู่ งาน Windows เรียกใช้บัญชี game_ ที่กำลังลงชื่อเข้าใช้ ไม่เก็บรหัสผ่าน Windows ทำงานเมื่อใช้แบตเตอรี่ เริ่มชดเชยเวลาที่พลาดเมื่อเครื่องพร้อม และลองใหม่ได้ 3 ครั้งห่างครั้งละ 5 นาที ต้องเปิดเครื่อง ลงชื่อเข้าใช้ และเชื่อม Tailscale/SSH ได้จึงจะคัดลอกสำเร็จ หากปิดเครื่อง/ออกจากระบบจะยังมี backup รายวันบน Pi และคัดลอกชุดล่าสุดเมื่อกลับมาเปิดเครื่อง งานนี้ไม่ปลุกเครื่องที่ปิดอยู่

## สิ่งที่สำรองและความเป็นส่วนตัว

Pi เก็บแต่ละชุดแยกใน `shared/backups/daily/<timestamp>/`; `latest` เป็น pointer ไปชุดที่สำเร็จล่าสุด จะเผยแพร่ pointer หลัง dump/ตรวจ SHA-256/package สำเร็จเท่านั้น

- `mealq.archive.gz`: MongoDB ฐาน `mealq` เท่านั้น
- `config/`: backend.env, compose.env, token ของ Tunnel, demo-credentials.json ถ้ามี และไฟล์ demo-credentials-*.json ปกติที่ไม่ใช่ symlink รวม crontab
- `deploy/` จาก release ที่ใช้งาน, สคริปต์ backup ที่ติดตั้งใน `operations/`, release path และ image IDs สำหรับประกอบการกู้คืน
- `manifest.json`: จำนวนเอกสารแต่ละ collection ที่ mongodump รายงาน, `SHA256SUMS`, package.tar.gz และ package.sha256

ไดเรกทอรีบน Pi มีสิทธิ์ 700 และไฟล์ 600 ข้อมูลส่วนตัวอยู่ใน backup จึงต้องรักษาสิทธิ์เหล่านี้ ไม่ส่งขึ้น Git หรือบริการภายนอก Windows รับ package ผ่าน SSH โดยตรงเข้าสตรีมเข้ารหัส ไม่สร้างไฟล์ package ที่เป็น plaintext ระหว่าง backup ใช้ AES-256-CBC พร้อม HMAC-SHA256 แบบ encrypt-then-MAC แต่ละชุดมี key สุ่มใหม่และป้องกัน key ด้วย Windows DPAPI ของผู้ใช้ปัจจุบัน จากนั้นทดลองถอดรหัสในหน่วยความจำและตรวจ SHA-256 อีกครั้ง

Windows เก็บ `*.mealq` ใน `C:\Users\game_\MealQBackups` จำกัด ACL เฉพาะ game_, SYSTEM และ Administrators พร้อมรายงาน `sync-*.json` / `sync-failed-*.json` ไม่มี secret ในรายงาน หาก backup ล่าสุดบน Pi เก่าเกิน 36 ชั่วโมง งาน Windows จะแจ้งสถานะล้มเหลวในรายงาน/Task Scheduler แม้จะเก็บ encrypted copy ไว้แล้ว

DPAPI ผูกกับบัญชี/Windows profile และเครื่องนี้ ต้องรักษา Windows profile/DPAPI keys ไว้หากย้ายเครื่องหรือ reinstall Windows ไฟล์ `.mealq` เพียงอย่างเดียวไม่พอสำหรับถอดรหัสบนเครื่องใหม่ ขณะ Pi เสียยังสามารถกู้จาก Windows เครื่องนี้ได้ ห้ามล้าง Windows profile ก่อนจัดเตรียมการย้าย key หรือถอดรหัส archive ไว้ในพื้นที่สำรองส่วนตัวที่เหมาะสม

## ผลตรวจที่ทำแล้ว

- Backup จริงชุดแรก `20261019T184944+0700-214243` ตรวจ gzip และ SHA-256 ผ่าน
- Restore จริงใน MongoDB 4.4 container แยก `mealq-restore-drill-20261019T184949-214407` และฐาน `mealq_restore_drill_20261019T184949-214407`: ครบ **18 collections, 71 documents** ตรง manifest และคำสั่ง MongoDB validate ผ่านทุก collection
- Restore container ไม่มี host port, ใช้ `--network none`, volume ใหม่แยก และถูก stop หลังตรวจ เก็บ container/volume ไว้เป็นหลักฐาน ไม่มีการ drop/restore ไปยัง mealq จริง
- สำเนานอก Pi ชุด `20261019T185413+0700-217249` มี **18 collections, 105 documents**; ถอดรหัส archive ในไดเรกทอรีทดสอบใหม่บน Windows และตรวจ SHA-256 ของไฟล์ใน package ครบ 16 ไฟล์ ไม่ extract ไฟล์ config ออกมาเป็นรายไฟล์
- เปลี่ยน ciphertext ในสำเนาทดสอบแล้วถูก HMAC ปฏิเสธตามที่ควร
- เรียก Task Scheduler จริงด้วย Start-ScheduledTask แล้วได้ LastTaskResult=0 ไม่ได้ตรวจเฉพาะการรันสคริปต์ด้วยมือ
- คงไฟล์ทดสอบ/ไฟล์ไม่สมบูรณ์จากความพยายามแรกไว้ทั้งหมด ไม่มีการลบทิ้ง ชุดปัจจุบันอยู่ใน `C:\Users\game_\MealQBackups`; ชุดทดลองแรกใน AppData ถูกเก็บไว้ แต่เลิกใช้เป็นตำแหน่งงานประจำ เพราะ AppData ถูก virtualize ข้ามบริบทโปรแกรม

ผล restore/metadata เก็บใน `shared/backups/restore-drills/<timestamp>/`; หลักฐานฝั่ง Windows อยู่ใน `MealQBackups\restore-check-*` และ `integrity-check-*` ไฟล์ package ที่ถอดรหัสสำหรับ drill ยังคงเป็นข้อมูลส่วนตัว อยู่ภายใต้ ACL เดียวกัน

## ตรวจและเรียกด้วยมือ

```sh
# บน Pi: สร้างชุดใหม่โดยเก็บชุดเดิมไว้ทั้งหมด
sh /home/linapspi4/mealq-app/shared/operations/backup-pi.sh
crontab -l
tail /home/linapspi4/mealq-app/shared/backups/daily.log

# ทดลองกู้ซ้ำเฉพาะเมื่อต้องการพิสูจน์ชุดใหม่: ใช้ container/database/volume ใหม่เสมอ
sh /home/linapspi4/mealq-app/shared/operations/backup-restore-drill.sh
```

```powershell
# บน Windows PowerShell 7+
& "$env:USERPROFILE\MealQBackups\operations\backup-sync-windows.ps1"
Get-ScheduledTaskInfo -TaskName MealQ-OffPi-Backup

# ถอดรหัสเพื่อกู้คืน: เลือก OutputPath ใหม่ที่ยังไม่มีไฟล์ ห้ามใส่ path ของฐานจริง
& "$env:USERPROFILE\MealQBackups\operations\backup-decrypt-windows.ps1" `
  -Archive "$env:USERPROFILE\MealQBackups\<timestamp>.mealq" `
  -OutputPath "$env:USERPROFILE\MealQBackups\<new-private-directory>\package.tar.gz"
```

เมื่อกู้จริง ให้ตรวจ package SHA-256 และ SHA256SUMS ก่อน แยก staging/container/database ใหม่ก่อนเสมอ ตรวจจำนวนเอกสารจาก manifest และ MongoDB validate ให้ผ่าน สำรองฐาน/ค่า config ปัจจุบันก่อนสลับระบบจริง และคืน secret ด้วยไฟล์ 600 การกู้ไปยังฐานจริงเป็นการเปลี่ยนแปลงที่เสี่ยง จึงไม่รวมอยู่ใน drill นี้

## ข้อจำกัดและการเก็บระยะยาว

MongoDB ปัจจุบันเป็น standalone; mongodump ระหว่างเปิดใช้งานเป็นการคัดลอกระดับ collection ไม่ใช่ snapshot ทุก collection ณ วินาทีเดียวกัน การทดลองกู้ยืนยันไฟล์ โครงสร้าง และจำนวนเอกสาร ไม่รับประกันความสอดคล้องข้าม collection หากมีการเขียนระหว่าง dump หากต้องการ point-in-time recovery ต้องวางแผน replica set/oplog หรือ storage snapshot ที่สอดคล้องกันเพิ่มเติมโดยสำรองและประเมินผลกระทบก่อน

ไม่ตั้งการลบอัตโนมัติทั้งสองเครื่องตามคำสั่งผู้ใช้ เก็บทั้ง archive และไฟล์ประกอบจึงใช้พื้นที่ประมาณสองเท่าของ package ต่อชุด ควรตรวจพื้นที่ทุกเดือนและเก็บชุดรายวันอย่างน้อย 30 ชุด + รายเดือน 12 ชุดตามพื้นที่ที่มี ก่อนลดชุดเก่าต้องคัดลอกไปตำแหน่งส่วนตัวอื่น ตรวจ checksum และทดลองอ่านก่อนทุกครั้ง ห้ามใช้ `rm -rf`, `compose down -v`, ลบ volume ฐานจริง หรือ cleanup แบบครอบคลุมโปรเจคอื่น งาน backup จะหยุดพร้อมเก็บชุดไม่สมบูรณ์หากพื้นที่ว่างต่ำกว่า 1 GiB; drill ใหม่ต้องมีพื้นที่ 2 GiB และหน่วยความจำว่างอย่างน้อย 1 GiB

Pi kernel แจ้งว่า Docker memory limit ใช้ไม่ได้ จึงไม่ถือว่า `--memory` เป็นขอบเขตที่รับประกันได้ สำหรับ drill จำกัด WiredTiger cache 0.25 GiB และ CPU 0.5 พร้อมตรวจ MemAvailable ก่อนเริ่ม งานจริงที่ทำผ่านแล้วไม่ได้เปลี่ยนหรือ restart container ของโปรเจคอื่น
